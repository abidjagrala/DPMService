### 2. Client User Permission Fix

Client users were getting 403 errors because the permission engine only
checked `UserRoleAssignment` objects. Client users had no role assignments
in the RBAC system.

#### Fix
Added `_apply_role_based_defaults()` in `permission_engine.py` that provides
scoped permissions based on `User.role` when no `UserRoleAssignment` exists:

| Role | Modules | Models |
|------|---------|--------|
| admin/superuser | All | All |
| manager | All | All |
| staff | dashboard, tickets, assets, devices, domain_hosting | serviceticket, asset, networkdevice, domainhosting |
| client | dashboard, tickets, assets | serviceticket, asset |

---

### 3. Client User Ticket Form Fix

Client users were getting a 505/500 error when creating tickets because
`_ticket_form_partial.html` always tried to render a `client` field, but
`ClientTicketForm` doesn't have one (client is auto-assigned).

#### Fix
- Changed `{% if form.client is defined %}` to `{% if "client" in form.fields %}`
  (Django templates don't support `is defined`)
- Made rest fields visible immediately when no client field exists
- Updated JavaScript to handle missing client input

#### File Modified
| File | Change |
|------|--------|
| `tickets/templates/tickets/_ticket_form_partial.html` | Conditional client field rendering |

### 4. Error Management System

Created styled error pages for all HTTP error codes, replacing white blank pages.

#### Files Created
| File | Purpose |
|------|---------|
| `accounts/templates/accounts/400.html` | Bad Request page |
| `accounts/templates/accounts/403.html` | Permission Denied page |
| `accounts/templates/accounts/500.html` | Server Error page |

#### Files Modified
| File | Change |
|------|--------|
| `dpmservice/views.py` | Added `custom_400`, `custom_403`, `custom_500` handlers with `_safe_render()` fallback |
| `dpmservice/urls.py` | Registered all error handlers (`handler400`, `handler403`, `handler404`, `handler500`) |

#### Error Handler Features
- All handlers use `_safe_render()` which catches template rendering errors
- Falls back to inline HTML if template fails (prevents white screen in production)
- All errors logged with `logging` module

---

### 5. Ticket Delete View Security

`ticket_delete_view` had **no authentication or authorization check** —
any unauthenticated user could delete tickets.

#### Fix
Added `@module_required('tickets', 'delete')` + `@model_required('serviceticket', 'delete')`.

---

### 6. Inline Permission Checks

All inline `HttpResponseForbidden(...)` calls in ticket views replaced with
`render(request, 'accounts/403.html', status=403)` for consistent error pages.

## Deployment Notes

After pulling these changes:

```bash
git pull origin main
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py shell -c "from authorization.services.permission_engine import clear_all_permissions; clear_all_permissions()"
touch dpmservice/wsgi.py
```

### Post-Deployment: Configure Permissions

Go to **Authorization > Permissions > Modules** and **Authorization > Permissions > Models**
to configure what each role can access. Until configured, the role-based defaults
(see section 2 above) will apply.

### Seeding Defaults

Run **Authorization > Seed Defaults** to populate the new modules/models in the
authorization system.
